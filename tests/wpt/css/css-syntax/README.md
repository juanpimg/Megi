# Vendored WPT CSS Syntax fixtures

These files are unmodified copies of the upstream [web-platform-tests](https://github.com/web-platform-tests/wpt)
CSS Syntax tests. They are **vendored as conformance fixtures** so that a clean clone of Megi can run
the CSS Syntax closed-loop gate offline (`cargo test -p megi-test-harness`) with no network access.

- Upstream: [web-platform-tests/wpt](https://github.com/web-platform-tests/wpt), pinned to commit
  `ab2ef95d3a7c512a6e7321688c80e428086af426` (2019-01-25) — never `master`.
- Byte verification: every vendored copy matches the raw file at that pinned commit; SHA-256 hashes
  are recorded in `../MANIFEST.json` and `../NOTICE.md`. `tools/vendor_wpt.py --check` re-verifies
  them offline on every CI run.
- Per-file byte counts and hashes are in `../NOTICE.md` (generated by `tools/vendor_wpt.py`).

Only this directory is tracked under `tests/wpt/`; the rest of any local WPT sparse checkout stays
ignored (see the `tests/wpt/*` block in the repository `.gitignore`).

## What the harness executes (`crates/test_harness`)

The fixture files are read from disk at test time; if any of them is missing the gate **fails**
(it does not silently skip). The CSS section contributes exactly **100 results**, all produced by
`crates/test_harness/src/css_harness.rs` and its `expanded` submodule:

| Fixture | Results | How it is exercised |
|---|---|---|
| `declarations-trim-whitespace.html` | 9 | The `<style id="style-el">` block is parsed with `megi_html::parse_document`, the stylesheet is parsed with the `css` crate, and `--foo-1`..`--foo-9` must trim to `bar`. |
| `input-preprocessing.html` | 13 | The 10 upstream `testParsing(...)` cases are extracted from the file's script and replayed through `megi_css::preprocess_css_codepoints` (5 NULL and 5 lone-surrogate cases), plus 3 newline-normalization cases (CRLF/CR/FF) that upstream cannot express in JS. |
| `anb-parsing.html` | 58 | 58 of the 67 upstream `testANB(...)` cases are extracted and replayed: `:nth-child(<input>)` goes through `megi_css::parse_selectors`, the resulting `AnPlusB { a, b }` is serialized to `An+B` text and compared with the upstream `selectorText` expectation. Invalid inputs must yield the upstream `parse error` sentinel. The 9 cases listed below are excluded, not reported as PASS. |
| `anb-serialization.html` | 20 | All 20 upstream `testANB(...)` roundtrip cases are replayed through the same engine parser and serializer. |
| **Total** | **100** | |

This is an honest 100-check gate, not a claim of full WPT coverage. Known engine limitations
(explicitly excluded from the denominator, never counted as PASS):

- `anb-parsing.html`: 9 upstream inputs that CSS Syntax §9 requires to be rejected as parse errors
  are currently accepted by Megi's selector parser: `+ n`, `+ n-5`, `+ n +5`, `n 5`, `-n 5`,
  `+ n- 5`, `+ n + 5`, `2 n + 2`, `+2 n`. They are listed in `UNIMPLEMENTED_ANB_INPUTS` in
  `crates/test_harness/src/css_harness/expanded.rs`, together with a check that upstream still
  expects `parse error` for each one. Fixing the selector parser's whitespace rejection is
  follow-up work outside this WP.
- `charset-is-not-a-rule.html`: not vendored. Megi's stylesheet parser leaves 4 rules instead of
  dropping `@charset` during preprocessing (upstream expects 1).
- `ident-three-code-points.html` and `unicode-range-selector.html`: not vendored. They require
  `getComputedStyle`, which the engine does not expose yet.

The omissions live in `EXCLUDED_PATHS` in `tools/vendor_wpt.py`, so they are visible in the diff
instead of silently reducing coverage. `META.yml` is vendored as `kind=skip` (upstream metadata,
not a test).

Commands (from the repository root):

```bash
cargo test -p megi-test-harness                 # closed-loop tests, including the CSS gate
cargo run -p megi-test-harness -- --summary     # CLI report; exit 0 only if failures are allowlisted
cargo run -p megi-test-harness -- --summary --strict   # any failure (even allowlisted) => exit 1
```

## Refreshing the fixtures

```bash
pin=$(python3 -c 'import json;print(json.load(open("tests/wpt/WPT-REVISION.json"))["revision"])')
base="https://raw.githubusercontent.com/web-platform-tests/wpt/$pin/css/css-syntax"
for f in declarations-trim-whitespace.html input-preprocessing.html anb-parsing.html \
         anb-serialization.html; do
  curl -fsSL "$base/$f" -o "tests/wpt/css/css-syntax/$f"
done
python3 tools/vendor_wpt.py --check
```

The pin comes from `tests/wpt/WPT-REVISION.json`; a refresh must keep it (or move it explicitly in
a reviewed WP together with `tests/wpt/MANIFEST.json`). After refreshing, re-run
`cargo test -p megi-test-harness`; the extractors in `crates/test_harness/src/css_harness.rs` and
`crates/test_harness/src/css_harness/expanded.rs` fail loudly if the expected number of upstream
cases changes (67 `testANB` cases in `anb-parsing.html`, 20 in `anb-serialization.html`, 10
`testParsing` cases in `input-preprocessing.html`).
