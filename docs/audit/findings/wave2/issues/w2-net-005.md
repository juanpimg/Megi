[net] decode_frame acepta texto inválido en UTF-8 y recv_text lo enmascara con lossy

## Resumen
`decode_frame` no valida UTF-8 en frames de texto (RFC 6455 §5.6: MUST ser UTF-8
válido) y `WebSocket::recv_text` convierte con `String::from_utf8_lossy`
(`websocket.rs:664`), sustituyendo bytes inválidos por U+FFFD en silencio.

## Impacto
P2 — contrato roto en dos capas: el frame inválido entra y la API string lo
corrompe silenciosamente en vez de fallar con error de protocolo.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R3), o:
   `decode_frame(&[0x81, 0x02, 0xFF, 0xFE], 1024)` → `Ok`.

## Esperado vs observado
Esperado: `Err` de protocolo en `decode_frame`; `recv_text` nunca devuelve U+FFFD forjado.
Observado: `R3 invalid-utf8-text-accepted: true`.

## Evidencia literal
```
R3 invalid-utf8-text-accepted: true
```
Código: `websocket.rs:318-373` sin `str::from_utf8` para `Opcode::Text`; `:664`
`from_utf8_lossy`.

Commit: 3c06db8

## Workaround
Validar UTF-8 en el llamante con `str::from_utf8(&frame.payload)` y cerrar con 1007.
