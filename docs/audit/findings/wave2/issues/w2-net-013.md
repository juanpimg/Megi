[net] parse_challenge rompe realm con coma entre comillas

## Resumen
`parse_challenge` (`crates/net/src/auth.rs:25-51`) corta la cabecera por `,` antes de
buscar `realm=` (`:26` `value.split(',').next()`), así `Basic realm="a,b"` pierde el
resto y el realm queda en `Some("a")` (o el challenge se clasifica mal con listas
`Digest realm="a", Basic realm="b"` → toma `digest` con realm `a`, documentado pero
frágil ante comas citadas).

## Impacto
P3 — parsing incorrecto de challenges con realm citado que contiene coma; realm
erróneo mostrado/almacenado y posible downgrade de esquema percibido.

## Pasos para reproducir
1. `parse_challenge("Basic realm=\"a,b\"")` → realm `Some("a")` en vez de `Some("a,b")`.

## Esperado vs observado
Esperado: `Some(AuthChallenge { scheme: "basic", realm: Some("a,b") })`.
Observado: `Some(... realm: Some("a"))` (corte en la coma citada).

## Evidencia literal
Código: `auth.rs:26` (`value.split(',').next()`) corre antes del parseo de comillas
(`:37-43`); el test `:126` solo cubre el caso sin coma.

Commit: 3c06db8

## Workaround
Evitar realms con coma; si el servidor los usa, el realm se truncará.
