[net] decode_frame acepta Close con payload de 1 byte (RFC exige 0 o ≥2)

## Resumen
`decode_frame` no valida el payload de Close: `[0x88, 0x01, 0x03]` (1 byte, ni vacío
ni código de 2 bytes) se acepta. RFC 6455 §5.5: el cuerpo de Close es 0 bytes o
2+ bytes con código válido.

## Impacto
P2 — contrato roto: se acepta y propaga un cierre malformado que un peer conforme
nunca envía.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R9), o:
   `decode_frame(&[0x88, 0x01, 0x03], 1024)` → `Ok`.

## Esperado vs observado
Esperado: `Err("websocket: ...")`.
Observado: `R9 one-byte-close-accepted: true`.

## Evidencia literal
```
R9 one-byte-close-accepted: true
```
Código: `websocket.rs:318-373` sin rama de validación para `Opcode::Close`.

Commit: 3c06db8

## Workaround
Validar `payload.len() == 0 || len >= 2` en el llamante antes de procesar Close.
