[net] decode_frame acepta frames con RSV1/2/3 activos sin extensión negociada

## Resumen
`decode_frame` (`crates/net/src/websocket.rs:318-373`) nunca inspecciona los bits
RSV1/2/3 (`bytes[0] & 0x70`). Un frame con `0xC1` se decodifica como texto válido
cuando RFC 6455 §5.2 exige fallar si no hay extensión negociada (y aquí nunca la hay).

## Impacto
P2 — contrato roto: se aceptan frames reservados que un peer conforme jamás envía;
puerta a extensiones fantasma y divergencia de interoperabilidad.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R2), o:
   `decode_frame(&[0xC1, 0x01, b'a'], 1024)` → `Ok`.

## Esperado vs observado
Esperado: `Err("websocket: reserved RSV bits")`.
Observado: `R2 rsv-bits-accepted: true`.

## Evidencia literal
```
R2 rsv-bits-accepted: true
```
Código: `websocket.rs:322-323` extrae `fin` y `opcode` pero jamás `bytes[0] & 0x70`.

Commit: 3c06db8

## Workaround
Ninguno en la API actual; validar RSV en el llamante antes de confiar en el frame.

## Dedup
Dedup: new (rel. #1534 abierta, tracker de WebSocket). Mesa A: VERIFIED. Mesa B: SOLO NUEVO, P2 mantener.
