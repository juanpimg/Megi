[fuzz] el oráculo del fuzz target `charset` es falso positivo y aborta cada campaña (BOM ⇒ sin U+FFFD contradice decodificación lossy)

## Resumen
El oráculo de `fuzz/fuzz_targets/charset.rs:44-49` exige que una entrada con BOM UTF-8 nunca decodifique a un carácter de reemplazo (U+FFFD). Eso contradice la decodificación lossy documentada del producto: `crates/render/src/charset.rs:32-39` pela el BOM (WHATWG Encoding §13.2) y decodifica el resto con `String::from_utf8_lossy`, donde bytes inválidos tras el BOM producen U+FFFD de forma correcta.

## Impacto
P2 (infra-only, harness). La campaña `cargo fuzz run charset` aborta al primer input con BOM + bytes inválidos posteriores y enmascara bugs reales del decodificador (clase del ya sufrido #1212, prescan panic). Etiquetas: `fuzz`, `test`. Nunca `security`/producto: el producto decodifica bien, el roto es el oráculo.

## Pasos para reproducir
1. `printf '\xEF\xBB\xBF\xFF\xFE\x3C\x00\x00\x00\x00\x00\x38' > /tmp/w2-t-01-input.bin` (12 bytes, base64 `77u///48AAAAAAA4`).
2. `cd fuzz && cargo +nightly fuzz run charset /tmp/w2-t-01-input.bin` (replay de 1 archivo; la campaña completa `-max_len=4096 -runs=5000` aborta igual al primer input de esta forma).
3. Alternativa documentada en el informe: `cargo +nightly fuzz run charset -- -max_len=4096 -runs=5000` → crash `exit status: 77`.

## Esperado vs observado
Esperado: tras pelar el BOM, `rest = FF FE 3C 00…` es UTF-8 inválido → U+FFFD inicial es el resultado correcto (`strip_prefix(BOM)` + `from_utf8_lossy`); el texto no empieza por U+FEFF, luego el BOM sí fue pelado. El oráculo debería comprobar `!decoded.text.starts_with('\u{FEFF}')`.
Observado: panic del oráculo aunque la decodificación es correcta; la campaña no puede completarse.

## Evidencia literal
```
thread '<unnamed>' panicked at fuzz_targets/charset.rs:45:17:
a UTF-8 BOM must not decode to a replacement character
Error: Fuzz target exited with exit status: 77
```
Comprobación en Python (Mesa A): tras pelar el BOM, `starts with FFFD: True`. Fix propuesto: relajar el oráculo a `!decoded.text.starts_with('\u{FEFF}')`, y si se quiere verificar ausencia de FFFD, exigirlo sólo cuando `rest` sea UTF-8 válido.
