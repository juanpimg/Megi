[net] Códigos de cierre entrantes nunca se validan (1005/1006/1015 aceptados)

## Resumen
`decode_frame` (`websocket.rs:318-373`) devuelve el payload de Close tal cual, sin
comprobar que los 2 primeros bytes sean un código válido ni rechazar los reservados
1005/1006/1015 (que RFC 6455 §7.4 prohíbe en el wire). Complementa a w2-net-006/009:
ni el envío ni la recepción validan códigos.

## Impacto
P2 — contrato roto: un peer puede inyectar un Close con código reservado y el cliente
lo propaga como si fuera legítimo.

## Pasos para reproducir
1. `decode_frame(&[0x88, 0x02, 0x03, 0xED], 1024)` (código 1005 en el wire) → `Ok`
   (inspección + llamada directa; `decode_frame` es `pub` y no tiene rama Close).

## Esperado vs observado
Esperado: `Err` (1005 MUST NOT appear on the wire).
Observado: `Ok` con `payload == [0x03, 0xED]`.

## Evidencia literal
Código: `websocket.rs:318-373` — cero referencias a `close_code` en el path de
recepción; el validador `is_valid_outgoing` (`:272`) solo se usa en tests (`:570-573`).

Commit: 3c06db8

## Workaround
Validar el código en el llamante con `close_code::is_valid_outgoing` y tratar
1005/1006/1015 como error de protocolo (1002).
