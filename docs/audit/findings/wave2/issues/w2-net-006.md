[net] WebSocketClient::close envía códigos reservados (1005) sin validar

## Resumen
`close(code)` (`websocket.rs:200-203`) serializa cualquier `u16` sin pasar por
`close_code::is_valid_outgoing` (`:272-274`), que existe pero nadie llama fuera de tests.
Enviar 1005/1006/1015 viola RFC 6455 §7.4 y un peer estricto cerrará la conexión.

## Impacto
P2 — contrato roto: la propia API fabrica frames de cierre ilegales.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R5): handshake real
   contra servidor local y `client.close(1005)` → `Ok`, el servidor lo recibe.

## Esperado vs observado
Esperado: `close(1005)` → `Err` (código reservado, no enviable).
Observado: `R5 reserved-close-1005-sent: true`.

## Evidencia literal
```
R5 reserved-close-1005-sent: true
```
Código: `websocket.rs:200-203` (`code.to_be_bytes()` sin check); validador en `:272` sin uso.

Commit: 3c06db8

## Workaround
Llamar solo con 1000-1011 válidos o 3000-4999; comprobar `is_valid_outgoing` antes.
