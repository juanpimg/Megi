[net] recv traga errores de protocolo y bloquea hasta el timeout en vez de fallar

## Resumen
`WebSocketClient::recv` (`websocket.rs:175-193`) usa `if let Ok((frames,_)) =
decode_frames(...)`: cuando el stream contiene un frame inválido (p. ej. frame de
servidor con MASK, violación de protocolo), el `Err` se ignora y el loop sigue
leyendo hasta agotar el `read_timeout`, devolviendo un `Io` de timeout en vez del
error de protocolo inmediato.

## Impacto
P1 — hang efectivo: un solo frame malformado convierte `recv` en un bloqueo de
`read_timeout` (2s por defecto) con un error engañoso; un peer malicioso lo convierte
en DoS del pump.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R6): servidor que
   envía frame maskeado y calla; `recv()` tarda ~2s y devuelve error Io.

## Esperado vs observado
Esperado: `Err(InvalidResponse("websocket: server frame must not be masked"))` inmediato.
Observado: `R6 recv-after-masked-frame err="HTTP I/O error: Resource temporarily unavailable (os error 11)" after=2.016392856s (protocol error expected fast)`.

## Evidencia literal
```
R6 recv-after-masked-frame err="HTTP I/O error: Resource temporarily unavailable (os error 11)" after=2.016392856s (protocol error expected fast)
```
Código: `websocket.rs:179` (`if let Ok(...)`) descarta el `Err`.

Ninguno; el llamante no puede distinguir timeout real de protocolo tragado.
