[net] CredentialStore no normaliza origen: puerto por defecto explícito no coincide

## Resumen
`CredentialStore::{set,get}` (`crates/net/src/auth.rs:93-102`) clavea por string crudo
sin normalizar. Guardar en `"http://a.test"` y buscar `"http://a.test:80"` (mismo
origen) devuelve `None`: la credencial no se reenvía y el fetch cae en 401/retry.

## Impacto
P2 — contrato roto: fallo de autenticación intermitente según quién construya la
clave con o sin puerto por defecto.

## Pasos para reproducir
1. `cd /tmp/opencode/w2net-verify-A && cargo run --offline` (caso R8):
   `store.set("http://a.test","u","p"); store.get("http://a.test:80")` → `None`.

## Esperado vs observado
Esperado: `Some(("u","p"))` (mismo origen).
Observado: `R8 default-port-origin-miss: true`.

## Evidencia literal
```
R8 default-port-origin-miss: true
```
Código: `auth.rs:83-102` (`HashMap<String,_>` sin normalización; compárese con
`Origin::parse` en `cors.rs:46-85` que sí normaliza 80/443).

Commit: 3c06db8

## Workaround
Normalizar la clave en el llamante (elidir `:80`/`:443`) antes de `set`/`get`.

## Dedup
Dedup: new (rel. #1533 cerrada, auth limitada a Basic). Mesa A: VERIFIED. Mesa B: SOLO NUEVO, P2 mantener.
